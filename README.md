# CS-320-Software-Test-Automation-QA
CS 320 Software Test, Automation QA
# How can I ensure that my code, program, or software is functional and secure?
When I'm working on my software projects, I make sure everything runs smoothly and securely. I do this by using a lot of automated unit testing and a bit of defensive programming. I like to write thorough JUnit tests to check all the usual scenarios, edge cases, and error situations, aiming to cover as much of the code as possible. 
On top of that, I focus on building security right into my code. I make sure to validate inputs strictly, enforce the right data types, set length limits, and keep things from being null at the entry points of my classes. This way, I can stop any bad data from messing things up. I also take care to handle errors cleanly, making sure the application can fail gracefully without spilling any sensitive system info.
# How do I interpret user needs and incorporate them into a program?
I like to take user needs and turn them into clear rules for the program. For example, if a requirement says an ID has to stay the same or a phone number has to be exactly ten digits, I make sure to build that into the validation checks. I pay close attention to the inputs users will give me and what they expect in return. By breaking down larger user stories into smaller, manageable pieces, I can continuously check my work against the requirements. This way, I can ensure everything works exactly as it's supposed to.
# How do I approach designing software?
When I’m designing software, I like to keep things pretty straightforward. I focus on modular architecture and making sure my data is well-organized. Before I dive into coding, I take the time to really understand the specs and figure out what objects, data structures, and services I need. I always make my classes private to protect their internal states and use constructors and methods that keep everything in check. This way, the core models are separate from the service layer, which makes it easy to maintain, scale, and test different components without them crashing with each other.
